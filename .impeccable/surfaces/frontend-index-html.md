## Surface and mode

The local dashboard at `frontend/index.html`; Operate.

## Audience and job

Working assumption: a person evaluating or trying the local MailMind prototype wants to inspect the sample mail and agenda, then try the assistant endpoint.

## Task, content, and constraints

One page presents the local API state, sample inbox records, sample calendar events, and the SSE demo response. The visitor must be able to tell fixture data from personal data. Chat is a placeholder, and actions are disabled. Keep navigation, request status, errors, and empty/loading states visible and accessible.

## Direction and memorable moment

Use the grammar of a rail-concourse split-flap board: fixed reading columns, matte graphite surfaces, painted white type, restrained amber lamps, and a single narrow wayfinding rail. The user can read the sample mail and upcoming schedule as one continuously scanned board, then submit a question without implying live account access.

## Unresolved

The eventual user audience, connected-account workflow, and visual brand are not established.
